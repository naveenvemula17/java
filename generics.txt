In Java, upcasting and downcasting are type conversions between a parent class and a child class. They’re mainly used with inheritance and polymorphism.
They should be parent and child classes objects.

Upcasting : Child object → Parent reference
    Object obj = new String();

    int a      = 25;
    long num   = a;

Downcasting : Parent reference → Child reference

    String str = new Object();       // compiler error.

    Object obj = 10;
    String str = (String) obj;      // ClassCastException.

        Integer object 10 is at object reference obj because Object reference can store Integer object (Integer is subclass of Number and Number is subclass of Object.) 
        Here (String ) says treat this obj as a String,but obj is Integer object so here casting exception raises.

-> When we want to create a variable which can take any datatype we use object.it has getters and setters as well and in getters while accessing we added 5 while printing 

    obj.getValue() + 5; even though value is Integer we get error because if it was boolean it makes no sense to use + operator.

    <T> - Type parameter.

    1. Generics in class.

        class Main {
            public static void main(String[] args) {
            Check<Integer> obj = new Check<>(49);
            System.out.println(obj.getValue() + 1);
            }
        }

        class Check <T> {
            private T value;
            Check(T value){
                this.value = value;
            }

            T getValue(){
                return this.value;
            }

            void setValue(T value){
                this.value = value;
            }
        }

    2. Generics in method.

            public static void main(String[] args) {
                int x = info(77,"naveen");
                System.out.println(x);
            }

            static <T,U> T info(T val,U valu){
                System.out.println(valu + " is my name");
                return val;
            }

        here java automatically treats arguments as Integer and string this is called inference.

Java generic types are invariant by default.

    List< Dog > is not a subtype of List< Animal >

    < ? extends Parent class> parent class is the upper bound. methods of only upper bound class can be called.
    < ? super Classname >     classes which are super classes of classname. 
    < ? super Animal >       classes which are super classes of Animal and above.
    extends and super are opposite.

    COVARIANCE :

        Covariance means: if B is a subtype of A, then a type involving B can also be treated as a subtype of the corresponding type involving A.

        1.String[] strings = {"A", "B"};

          Object[] objects = strings;  // Valid
        
            String extends Object
            String[] extends Object[]

            But there is a runtime danger:

            Object[] objects = new String[2];

            objects[0] = 10;  // ArrayStoreException

            -> Java allows us to assign array of strings(subclass) to array of objects (superclass reference) is called covariance.However it is going to give exception when we modify an element number to number.

    INVARIANCE :

        Java generics are invariant by default.

        String extends Object

        List<String> extends List<Object>   // ❌ No

        List<String> strings = new ArrayList<>();

        List<Object> objects = strings;  // ❌ Compile-time error

        Why? If this were allowed, you could do:

        objects.add(123);

        and put an Integer into a List<String>.

        -> when you assign list of strings to list of objects it will be a error, because dont allow it the reason for it is we can add integers values to list of objects,here there will be no type safety.so java dont allow.

    3.Covariance with ? extends

        Java provides covariance for generics using a wildcard:

        List<String> strings = new ArrayList<>();

        List<? extends Object> objects = strings;  // ✅

        You can read safely:

        Object value = objects.get(0);

        But you generally cannot add values:

        objects.add("Hello");  // ❌

        A useful rule is:

        ? extends T → Producer → you can read T   

        -> Through extends wildcards in generics java allows covariance for subtypes of defined class.And it is read only, we cannot change.

    4.Covariance with ? super :

        It is opposite of ? super.

        Java allows assigning of list of objects to list of strings using <? super String >,we can write into it and read also but we get type object while reading.

            List<Object> objects = new ArrayList<>();

            List<? super String> strings = objects;  // ✅

            strings.add("Hello");  // ✅

            You can safely add String, but when reading, you only know that the result is an Object:

            Object value = strings.get(0);

    PECS rule :

        Producer extends consumer super.

        Producer extends means while using extends with wildcards, extends lets us only read the data which is produced.
        consumet super means data needed to be consumed by it.so we need to add data to it.
    

    Type erasers :

        Generics are compile time layer which jvm dont know,compiled code moves to jvm for execution and there will be no generics they will get replaced by object class or its sub types.

        Before converting to bytecode compiler understands generics and erases its type then it gets compiled and moves to jvm for running.
