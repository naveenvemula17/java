CALL BY VALUE vs.  CALL BY REFERENCE 

    call by value :
        when we call a method using variables the values of these variables copies to the method declaration and these wont affect the original variables.

    call by reference :
        when we call a method using variables the original variables are passed to the method declaration. hence
    original value gets changed.

    ----> java uses call by value.

SHALLOW COPY & DEEP COPY :

    we can pass an object to construtor

    Truck(Truck t){
        this.color =t.color;
        this.wheels=t.wheels;
    }

    Truck t1=new Truck();
    t1.color= black;
    t1.wheels=16;
    Truck t2=new Truck(t1); ---> deep copy.    (if we change values with t2, t1 values wont change.)
    Truck t3=t1             ---> shallow copy. (if we change values with t3, t1 values will change.)

INHERITENCE :

    use extends keyword to inherit parent class members.

    --> Code reusability.
    --> Supports polymorphism.

    Parent class -> super class 
    Child class  -> sub class.

    Protected access modifier used with parent class to excess its members by its child class outside of its package.

    TYPES OF INHERITENCE :

        1.Simple inheritence. A -> B 

        2.Multi-level inheritence A -> B -> C.

        3.Hierarchial inheritence.

                    A 
                   / \  
                  B   C 

        4. Multiple inheritence -> not supported by java, due to diamond problem.

        Diamond problem -> if a class is child of two or more classes then if the parent classes contain same members,so jvm couldnt configure which one to use when we call it in child class.

        To avoid this we have interfaces in java.

ABSTRACTION :

    The process of focussing on what something does rather than how it does.

POLYMORPHISM :

    same object behaves differently on same command but when one parameter is changed.

    Compile time polymorphism :

        While compiling which method to be taken is decided if there is method overloading.

    Run time polymorphism :

        method is chosen at runtime among overidden methods in child classes because object is created at runtime.

    -> For static methods java looks at reference type.

            Assume Vehicle contains static method kick() and Car also contains static method kick(), Vehicle v=new Car() the reference type method is called.

            if they are not static methods then the car's kick method is called which overriden in car class.

    -> Private methods cannot be overridden.
    -> Final methods cannot be overriden.
    -> Fields/variables cannot be polymorphic.
    -> final class - cannot be inherited by any child class.

WHY ONLY ONE PUBLIC CLASS :

    Java uses the public class name to determine the file name.

    The compiler expects the public class to match the filename so that classes can be easily located and compiled.

    if there are two public classes,java wouldnt know what file should be named.
    
PRIMITIVES vs. WRAPPER classes

    Wrapper classes in Java are classes that represent primitive data types as objects.

POJO CLASSES :

    POJO stands for plain old java object.

    class with simply variables and setters and getters methods,without any framework and business logic.

    A POJO is a simple Java class used mainly to store data. It generally does not need to extend a particular class or implement a particular interface.

    ✅ Private instance variables
    ✅ Public getters and setters
    ✅ Constructors (optional)
    ✅ No requirement to extend a specific class
    ✅ No requirement to implement a specific interface
    ✅ Usually used to represent/store data 

    Anemic model      : data + constructors + getters & setters + little /no business logic.
    Rich domain model : data + business logic.(methods like markAttendence in student class.)
    
NESTED CLASSES :

    Class inside another class.

    NEED :

        -> Logical grouping.
        -> better access of outer classes.(means inner class can access private memebers of outer class.)
    
    TYPES :

        STATIC NESTED CLASS :

            Assume it as a static block and as it is static we need to use it with classname.

            Assume Inner is the class inside of Outer class then we can create object of inner class by using :

                Outer.Inner = new Outer.Inner();

            -> we cant access non-static members of outer class directly. (if we access we will get error.)
            -> To access them we need to have reference of outer class.

            USES:

                1.used as helper class.
                2.used in builder design pattern.

        INNER CLASS :

            non-static class inside of static class.

            -> Inner class object always stores reference of outer class and inner class object is not inside of outer class object.

            -> Inner class can access static and non-static members of outer class.

            -> static members are not allowed upto java 16.because confusion of static members to should be same for all outer class objects.

            To access inner class members we need to create outer class object.

            Outer outer =new Outer();

            Outer.Inner inner = outer.new Inner(); or 

            Outer.Inner inner = new Outer().new Inner();

    LOCAL CLASSES :

        Class between {} is called local class. {} can be of any of if{},for{},fun(){}..

        -> It can access all static and non-static members of outer class.

        -> To access a local variable in local class it should be effectively final.

        effectively final variable :

            A local variable whose value is not modified after initializing.

            -> when local variable is initialised before class ,class copies the variable but when you modify it java confuses to copy which variable(old or updated.),to counter this we have effectively final variable.
            it copies because assume local class is in a function and it has some return type object and when we call it from outside function returns object,so to use its object members it copies.
